## 1. BorderFill 레코드의 대각선 종류 필드는 표 27이 아닌 표 25 기준이다.

명세서에서는 DocInfo의 BorderFill 레코드에서 4방향 테두리선 종류/굵기/색상 다음 대각선 종류/굵기/색상이 나온다고 명시하고 있다. 그러면서 테두리선 종류는 표 25를, 대각선 종류는 표 27을 각각 참고하라고 한다. 그러나 실제 파싱 결과, 대각선 종류도 표 25를 참조해야 한다는 것을 발견했다.

- macos용 한컴오피스 한글 12.30.0(6544) 기준, 명세서대로 파싱하면:
  - 빈 문서를 생성한 뒤 파싱하면 대각선의 종류가 1(BackSlash)로 나온다.
  - 문서에 1\*1 표를 생성한 뒤 별도의 대각선을 추가하지 않아도 대각선의 종류가 1(BackSlach)로 나온다.

  문서의 기본값으로 기본 대각선 값이 Backslash로 설정되어 있는 점이 어색하다. 그리고 BorderFill 레코드의 속성 필드에서 이미 대각선 모양(종류)를 갖고 있기 때문에 중복 데이터이다.

- 그래서 1\*1 표에 대각선을 부여한 뒤 선 스타일을 점선으로 부여한 뒤 파싱한 결과:
  - 대각선의 종류에 3이 찍혔다. 이는 HWP 파일 기준 점선에 해당한다.

그러므로 명세와 달리 대각선 종류는 표 27이 아닌 표 25를 참고해야 한다고 유추해볼 수 있다. 그래서 대각선 전용으로 사용하는 인터페이스인 DiagonalLine을 버리고, 4방향 테두리선에 사용하는 BorderLine을 다시 적용했다.

## 2. BorderFill의 Fill 필드의 채우기 종류는 배타적인가?

- 채우기 종류(type)은 명세와 일치함. 하지만 채우기 없음, 단색 채우기, 이미지 채우기, 그러데이션 채우기 필드가 배타적인지 표기되어 있지 않다.
  - 확인 결과, 한컴오피스 한글 프로그램에서는 배타적으로 저장하나, 모든 필드가 다 켜져있다고 해서 프로그램에서 오류를 발생시키지 않는다.
  - 단, 복수의 플래그가 켜져있을 때 어떤 화면을 보여줄지 우선순위가 있음을 확인했다.
  - 4가지 조합 (단색+이미지, 단색+그라디언트, 이미지+그라이언트, 단색+이미지+그라디언트)의 플래그 상태를 실험해보니 우선순위는 `이미지 > 그라디언트 > 단색` 임을 알 수 있었다. 이미지가 가장 우선한다. 다만 macos 한컴오피스 한글에서만 확인했으므로 Windows에서는 추가 확인 필요함.

## 3. BorderFill의 Fill 필드 (표 28)의 명세는 실제와 상당 부분 상이하다

- 단색 채우기의 무늬 종류는 명세 상 1~6 값을 갖는다고 되어있으나, 실제로는 -1~5값을 갖는다.
  - -1은 실제로 "무늬 없음"을 표현하는 값이나 명세화되어있지 않음
  - 1~6으로 작성된 무늬 종류는 실제로 Zero-indexed임. 그러므로 0~5로 고쳐야함.

- 그라데이션 채우기 필드의 자료형이 잘못 작성되어 있따. (아래 필드들은 명세서의 표기명을 그대로 인용함)
  - 그러데이션 유형 INT16 -> UINT8
  - 그러데이션의 기울임 INT16 -> INT32
  - 그러데이션의 가로 중심 INT16 -> INT32
  - 그러데이션의 세로 중심 INT16 -> INT32
  - 그러데이션의 번짐 정도 INT16 -> INT32 (명세서에서는 해당 필드에 지정 가능한 값으로 0-100을 명시하나, 실제 프로그램에서 확인한 결과 0-255를 지정 가능함)
  - 그러데이션의 색 수 INT16 -> INT32 (macos 한컴오피스 한글에서 3색 이상의 그라데이션 지정 불가하나, 실제로 존재하는 필드는 맞음)

- 이미지 채우기 필드에 관련없는 필드가 명시되어있다.
  - 이미지 채우기에 존재하는 DWORD(그라데이션 바이트), BYTE(그라데이션 번짐 정도) 필드는 관련없는 값임에도 불구하고 마치 이미지 채우기에 필요한 필드처럼 작성되어있다.
  - 마지막 두 필드는 앞서 말한 DWORD, BYTE와 중복되므로 명세에서 삭제해야 한다.
  - 실제로는 Fill 필드 뒤에 DWORD(그라데이션 바이트)가 항상 존재하고, 채우기 종류가 그라데이션일 때 0 -> 1로 지정된다. 뒤에 번짐 정도를 표현하는 1바이트가 더 있다는 의미이다.
  - BYTE는 그라데이션일 때만 추가된다. 번짐 정도를 표현한다. (0-100의 값을 가짐)

- 표 31의 이미지 채우기 유형
  - 값 15는 NONE이라고 되어있으나 실제 프로그램에서 "원래크기에 비례하여"임.

- 채우기 종류가 켜진 종류 수만큼 Fill 필드 가장 끝에 정체불명의 1바이트가 추가된다.
  - rhwp 라이브러리에서 투명도를 표현하는 alpha 값이라고 한다.
  - 궁금해서 해당 필드에 실제 바이너리 값을 주입한 결과, 프로그램에서 배경색의 투명도 변화가 없었다. (이건 macos 환경이라 그럴수도 있음)
  - 명세서에는 없지만 실제로 존재하는 필드이기에 alpha가 아닌 unknown으로 표기했다. 여러 파일 검사하며 검증 필요함.
