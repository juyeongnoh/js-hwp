# 한글 프로그램의 실제 동작

에디터 개발 참고용. 파일 형식(바이트 배치)은 `hwp-format.md`, 명세 오류는 `hwp-5.0-errata.md`에 있다. 여기에는 **한글이 무엇을 저장하고, 어떻게 읽고 그리는지** 관찰한 것만 적는다.

- 환경: macOS용 한컴오피스 한글 12.30.0(6544). Windows 동작으로 일반화하지 않는다.
- 각 항목 끝의 괄호는 근거다. 실험 파일은 `experiments/`에 있다.

## 새 문서의 기본값

- 빈 문서를 저장하면 BorderFill이 두 개 생긴다. 둘 다 네 방향 선 없음이다. 첫째는 채우기 없음, 둘째는 단색 채우기(배경 `FFFFFFFF`, 무늬색 `#999999`, 무늬 없음)다. (TIL 2026-10-29, 샘플 바이트)
- 대각선은 그리지 않아도 선 정보가 기본값으로 들어 있다: 실선(1), 0.1mm, 검정. 대각선을 그릴지는 속성 비트(`slashShape` 등)가 정한다. (TIL 2026-10-30)

## 셀 배경 채우기

- **UI는 하나만 고른다**: 채우기 없음, 색, 그러데이션, 그림 중 하나. 셀 채우기에 투명도 설정은 없다.
- **저장도 하나만 한다**: 다른 종류로 바꿔 저장하면 이전 종류의 블록이 지워진다. 그림에서 다른 종류로 바꾸면 `BinData`의 그림까지 지워진다. (실측 저장 파일)
- **편집 중에는 이전 값을 기억한다**: 그림 → 그러데이션 → 그림으로 바꾸면, 문서를 닫기 전까지는 이전 그림이 돌아온다. 파일에는 남지 않으므로 다시 열면 없다.
- **여러 종류가 켜진 파일도 연다**: 오류 없이 열고, **이미지 > 그러데이션 > 색** 순으로 하나만 쓴다. 본문에 그려진 모습과 속성 창 중 어느 쪽에서 본 결과인지는 구분해 기록하지 않았다. 종류 5는 속성 창에서도 그러데이션이었다. (`experiments/fill-multi-kind-priority`)
- **번짐 정도 0인 그러데이션은 그리지 않는다**: 속성 창 값은 정상으로 보인다. 50, 255는 그린다. 명세 범위(0–100)와 달리 255도 쓴다. (`experiments/fill-gradient-step-zero`)
- **macOS 한글은 그러데이션 색을 2개까지만 설정**할 수 있다. 3색 이상은 Windows에서 확인해야 한다.
- **채우기 끝의 알 수 없는 1바이트**는 0, 50, 128, 255로 바꿔도 표시가 같다. 한글은 이 값을 쓰지 않는 것으로 보인다. 저장할 때는 0을 쓴다. (`experiments/fill-trailing-unknown-byte`)

## 그림 채우기

- 채우기 방식 값 15는 UI에서 "원래 크기에 비례하여"로 표시된다.
- 그림 효과 드롭다운에 값 3(8×8 패턴)은 보이지 않는다.
- 그림 정보는 명암이 밝기보다 먼저 저장된다(명세와 반대).
