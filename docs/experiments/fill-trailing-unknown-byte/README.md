# 채우기 끝의 알 수 없는 1바이트

채우기 정보는 추가 채우기 속성 뒤에 명세에 없는 1바이트가 붙는다(채우기 없음에는 없다). rhwp는 이를 투명도로 해석한다. 한글에는 셀 채우기 투명도 설정이 없어서, 이 바이트만 바꿔 표시가 달라지는지 확인했다.

- 날짜: 2026-10-30
- 환경: macOS용 한컴오피스 한글 12.30.0(6544)
- 기반: `base-image.hwp`.
- 바꾼 곳: 네 번째 BorderFill 페이로드의 마지막 1바이트(오프셋 46), 원래 값 `00`

## 파일

| 파일             | 마지막 바이트                   | 결과        |
| ---------------- | ------------------------------- | ----------- |
| `base-image.hwp` | `00`                            | 기반        |
| `byte-50.hwp`    | `32` (0–100 척도의 중간을 가정) | 원본과 같음 |
| `byte-128.hwp`   | `80` (0–255 척도의 중간을 가정) | 원본과 같음 |
| `byte-255.hwp`   | `ff`                            | 원본과 같음 |

## 결론

이 바이트는 macOS 한글의 표시에 영향을 주지 않는다. 투명도라는 근거가 없으므로 모델에서는 `unknown`으로 원시 값만 보존한다. 한글이 저장한 파일에서는 단색, 그러데이션, 이미지 모두 `00`이었다.

## 재현

저장소 루트에서 실행한다.

```bash
node docs/experiments/scripts/make-alpha-variants.mjs "$PWD" docs/experiments/fill-trailing-unknown-byte/base-image.hwp <출력 폴더> 50,128,255
```

생성 이름 `fill-image-alpha-<값>.hwp`가 `byte-<값>.hwp`다. 2026-10-30에 이 폴더의 기반 파일로 다시 생성해 지금 파일들과 바이트가 같음을 확인했다.
