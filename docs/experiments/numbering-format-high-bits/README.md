# 번호 형식 위쪽 비트(bit 10~31)

번호 형식(bit 5~)이 몇 번째 비트까지 이어지는지 보려고, bit 5~9를 16으로 두고 그 위의 비트를 하나씩 켰다.

- 날짜: 2026-11-12
- 환경: macOS용 한컴오피스 한글 12.30.0(6544)
- 기반: `base-right-20mm.hwp`. 두 번째 문단 번호(`numbering[1]`) 1수준이 甲乙丙(16), 정렬 오른쪽, 번호 너비를 자릿수에 맞춤 끔, 자동으로 내어쓰기 끔, 너비 조정 20 mm(5669), 본문과의 간격 70 %, 글자 모양 아이디 7이다(속성 `0x202`). 한글이 저장한 원본은 이후 같은 파일에 다시 저장하면서 남지 않았다. `../numbering-format-high-bits/bit-10.hwp`에서 bit 10을 되돌려 복원했으므로 cfb 라이브러리가 다시 쓴 컨테이너이고 `Sh33tJ5` 스트림이 더해져 있다. 레코드와 다른 스트림 내용은 한글 저장본과 같다.
- 바꾼 곳: `numbering[1]`의 각 수준 문단 머리 정보 속성. `width-*.hwp`는 7개 수준 모두 bit 5~9를 16으로 바꾸고, 수준마다 다른 비트 하나를 켰다.

## 파일

결과는 사용자가 파일 단위로 알려 준 것이다. 수준별로 따로 기록하지 않았다.

| 파일 | 켠 비트 (1~7수준) | 설정 창 번호 모양 드롭다운 | 본문 |
| --- | --- | --- | --- |
| `bit-10.hwp` | 10 (1수준만) | 빈칸 | 1, 2, 3 |
| `width-11-17.hwp` | 11, 12, …, 17 | 빈칸 | 1, 2, 3 |
| `width-18-24.hwp` | 18, 19, …, 24 | 甲, 乙, 丙 | 1, 2, 3 |
| `width-25-31.hwp` | 25, 26, …, 31 | 甲, 乙, 丙 | 甲, 乙, 丙 |

## 결론

- bit 10~24를 켜면 본문은 1, 2, 3으로 그린다. bit 18~24는 설정 창에서 원래 값으로 보인다.
- 의심되나 확인되지 않음: 한글은 범위 밖 값을 기본값 0으로 처리하는 것 같다. 설정 창과 본문이 어느 비트까지를 번호 형식으로 읽는지, bit 18~24가 다른 필드인지는 확정하지 못했다.
- 한글 UI에서 고를 수 있는 값은 0~16뿐이라 한글이 저장하는 값은 bit 5~9 안에 들어간다. js-hwp는 bit 5~9만 읽고 쓴다.

## 재현

저장소 루트에서 실행한다.

```bash
npx tsx docs/experiments/scripts/patch-numbering-head.ts docs/experiments/numbering-format-high-bits/base-right-20mm.hwp <출력 폴더>/bit-10.hwp 1 0 10 10 1
```

`width-11-17.hwp`는 기반을 복사한 뒤 수준 i(0~6)마다 같은 파일을 입력과 출력으로 두 번 실행한다. 한 번은 `5 9 16`, 한 번은 `(11+i) (11+i) 1`이다. `width-18-24`, `width-25-31`은 시작 비트만 18, 25로 바꾼다. 2026-11-12에 이 폴더의 기반 파일로 다시 생성해 처음 만든 파일과 바이트가 같음을 확인했다.
