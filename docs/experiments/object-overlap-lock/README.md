# "쪽 영역 안으로 제한"과 "서로 겹침 허용"을 끌 수 있는 조건

개체 공통 속성 bit 13(쪽 영역 안으로 제한)과 bit 14(서로 겹침 허용)는 대화상자에서 비활성인 경우가 많다. 사용자가 그림에서 두 항목을 끌 수 없었다고 알려 줬다. 어떤 조건에서 바꿀 수 있는지, 개체 종류에 따라 다른지, 한글이 만들 수 없는 조합이 있는지 확인했다. 만들 수 없는 조합이 있으면 편집 API에서도 막아야 하기 때문이다.

- 날짜: 2026-11-19 (추가 실험도 같은 날)
- 환경: Windows용 한글 2024. 앱 버전은 기록하지 않았다.
- 기반: 한글 새 문서에 2×2 표(만들기 대화상자 기본값)를 넣었다. 이어서 사각형을 그리고, `solid-64.bmp`(스크립트로 만든 64×64 단색 BMP)를 "마우스로 크기 지정"을 끄고 그림으로 넣었다. 파일마다 앞 파일의 상태에서 대화상자를 다시 열어 바꾸고 다른 이름으로 저장했다.
- 바꾼 곳: 없음. 모든 파일은 한글이 저장한 그대로다.

## 대화상자 관찰

표/셀 속성, 개체 속성의 기본 탭에서 기준과 배치를 바꾸며 두 체크 상자를 눌러 봤다. 판단 근거는 체크 상자가 흐리게 그려지는지와 눌렀을 때 바뀌는지다.

| 조건 | 쪽 영역 안으로 제한 | 서로 겹침 허용 |
| --- | --- | --- |
| 세로 기준 문단 | 바꿀 수 있다 | 제한이 켜져 있을 때만 바꿀 수 있다 |
| 세로 기준 종이 또는 쪽 | 비활성. 값은 그대로 남는다 | 비활성. 값은 그대로 남는다 |
| 세로 기준 문단 + 제한 끔 | | 비활성. 켜져 있던 값은 켜진 채 남는다 |
| 글자처럼 취급 켬 | 비활성 | 비활성 |

- 표, 사각형, 그림, 글상자, 수식이 모두 같았다.
- 표·사각형·그림은 본문과의 배치 네 가지(어울림, 자리 차지, 글 앞으로, 글 뒤로) 모두에서 같았다. 글상자는 글 앞으로, 수식은 자리 차지에서만 봤다.
- 수식은 넣으면 글자처럼 취급이 켜져 있다(그래서 모두 잠긴다). 끄면 위 규칙대로 바뀐다. 새 글상자의 기본값은 사각형과 같다(글 앞으로, 종이 기준, 제한 끔·겹침 켬).
- 가로 기준(종이, 쪽, 단, 문단)은 두 항목의 활성 여부에 영향이 없었다(표에서 확인).
- 비활성이 되어도 체크 상태는 지워지지 않는다. 그래서 세로 기준을 문단으로 두고 값을 바꾼 뒤 종이·쪽으로 돌리면, 그 기준에서도 원하는 값으로 저장된다.

## 파일

"속성"은 CTRL_HEADER 오프셋 4의 UINT32 중 관련 비트다. 앞 파일의 개체가 뒤 파일에도 남아 있다.

| 파일 | 만든 순서 | 결과 |
| --- | --- | --- |
| `table-para-nolimit.hwp` | 표(자리 차지, 세로 문단)에서 제한을 끄고 겹침을 켠 뒤 제한을 다시 끔. 겹침은 흐린 체크로 남음 | 표: 세로 2, bit 13 = 0, bit 14 = 1 |
| `table-front-page-nooverlap.hwp` | 표를 글 앞으로, 세로 문단에서 제한 켬·겹침 끔, 그 뒤 세로 쪽 | 표: 세로 1, bit 13 = 1, bit 14 = 0 |
| `rect-paper-nooverlap.hwp` | 사각형(기본 글 앞으로, 종이 기준, 겹침 켜짐)을 세로 문단으로 바꿔 제한 켬·겹침 끔, 그 뒤 세로 종이 | 사각형: 세로 0, 가로 0, bit 13 = 1, bit 14 = 0 |
| `picture-page-nooverlap.hwp` | 그림(삽입 기본 어울림, 가로·세로 문단, 제한 켬, 겹침 끔)의 겹침을 켰다 끄고 제한을 껐다 켬, 그 뒤 세로 쪽 | 그림: 세로 1, 가로 3, bit 13 = 1, bit 14 = 0 |

`solid-64.bmp`는 그림 파일에 넣은 원본이다.

### 잠긴 값이 조판에 주는 영향

두 번째 새 문서에 사각형, 그림, 글상자, 수식을 넣었다. 대화상자 관찰 뒤 사각형 하나만 바꿔 저장했다. 판단 근거는 한글 편집 화면(쪽 윤곽 보기)에 그려진 모습이다.

| 파일 | 사각형 | 화면 |
| --- | --- | --- |
| `rect-paper-limit-off-270mm.hwp` | 세로 종이 270mm, bit 13 = 0 | 사각형이 1쪽 아래 끝에 걸쳐 쪽 밖으로 잘린다 |
| `rect-paper-limit-on-270mm.hwp` | 세로 종이 270mm, bit 13 = 1 | 위와 같다 |
| `rect-para-limit-on-270mm.hwp` | 세로 문단 270mm, bit 13 = 1 | 쪽이 2쪽으로 늘고 사각형이 2쪽 위에 그려진다 |
| `rect-para-limit-off-270mm.hwp` | 세로 문단 270mm, bit 13 = 0 | 1쪽뿐이고 사각형이 보이지 않는다(쪽 밖) |

- 종이 기준에서는 bit 13이 0이든 1이든 화면이 같았다. 잠긴 값은 조판에 영향이 없어 보인다.
- 문단 기준에서는 bit 13이 결과를 바꿨다. 켜면 개체가 쪽 영역 밖으로 나가지 않도록 다음 쪽으로 넘어가고, 끄면 쪽 밖에 그대로 놓인다.
- 네 파일에는 그림(어울림, 문단 기준), 글상자(종이 기준), 수식 두 개(하나는 본문, 하나는 글상자 안, 글자처럼 취급)도 들어 있다. 글상자의 개체 설명문 기본값도 "사각형입니다."였다.

## 결론

- **두 항목은 개체 종류와 관계없이 같은 규칙을 따른다.** 개체 종류에 따라 끌 수 있고 없는 것이 아니다.
- **"쪽 영역 안으로 제한"은 세로 기준이 문단일 때만 바꿀 수 있다.** 종이·쪽 기준에서는 비활성이다.
- **"서로 겹침 허용"은 세로 기준이 문단이고 "쪽 영역 안으로 제한"이 켜져 있을 때만 바꿀 수 있다.**
- **비활성인 항목도 값은 유지되어 저장된다.** 그래서 bit 13과 bit 14의 네 조합(0/0, 0/1, 1/0, 1/1)은 세로 기준과 관계없이 모두 한글로 만들 수 있다. 0/1은 `table-para-nolimit.hwp`, 종이·쪽 기준의 1/0은 나머지 세 파일로 저장해 확인했다. 종이·쪽 기준의 0/0, 0/1은 대화상자에서 흐린 상태로만 봤고 저장하지 않았다.
- 사용자가 그림에서 끌 수 없었던 것은 세로 기준이 종이나 쪽이었거나 제한이 꺼져 있었기 때문으로 보인다. 사용자가 본 그림의 기준은 확인하지 않았다.
- 편집 API 관점: 두 비트의 조합은 막을 필요가 없다. 한글이 막는 것은 값이 아니라 대화상자에서 바꾸는 순서다.
- 잠긴 bit 13은 종이 기준의 조판에 영향이 없었다. 문단 기준에서는 개체를 쪽 안에 두려고 다음 쪽으로 넘긴다.

**확인하지 않은 것**

- 글상자·수식의 다른 배치. 선, 타원, 다각형, 묶음 개체, OLE 등 그 밖의 개체.
- 잠긴 bit 14(겹침 허용)가 조판에 영향을 주는지. 쪽 기준에서 bit 13의 영향.
- 인쇄·PDF 출력에서도 화면과 같은지.

## 재현

파일은 한글에서 손으로 만들어 다시 생성할 수 없다. 개체 공통 속성은 아래 명령으로 풀어 볼 수 있다.

```bash
npx tsx docs/experiments/scripts/dump-object-common.ts docs/experiments/object-overlap-lock/table-para-nolimit.hwp docs/experiments/object-overlap-lock/table-front-page-nooverlap.hwp docs/experiments/object-overlap-lock/rect-paper-nooverlap.hwp docs/experiments/object-overlap-lock/picture-page-nooverlap.hwp docs/experiments/object-overlap-lock/rect-paper-limit-off-270mm.hwp docs/experiments/object-overlap-lock/rect-paper-limit-on-270mm.hwp docs/experiments/object-overlap-lock/rect-para-limit-on-270mm.hwp docs/experiments/object-overlap-lock/rect-para-limit-off-270mm.hwp
```

`solid-64.bmp`는 Node로 만든 64×64 24비트 BMP다(모든 픽셀 BGR `C8 78 28`).
