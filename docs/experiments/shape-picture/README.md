# 그림 개체 속성(SHAPE_COMPONENT_PICTURE)

그림 레코드(표 107~116)의 필드 배치와 뜻을 한글 대화상자 값, HWPX `hp:pic`과 대조했다. 결과는 정오표 정정 102~105, E53에 정리했다.

- 날짜: 2026-11-25
- 환경: Windows용 한글 2024. Mac에서 원격 데스크톱(Windows App)과 computer use로 조작했다.
- 그림: 직접 만든 120×80 4색 PNG(`quadrants.png`). 96dpi로 9000×6000 HWPUNIT이다.
- 만든 방법: 빈 문서에 그림을 넣어 `default`로 저장하고, 개체 속성 대화상자에서 아래를 차례로 바꿔 다른 이름으로 저장했다. 파일마다 .hwp와 .hwpx가 짝이다.
- 값 보기: `npx tsx docs/experiments/scripts/dump-pictures.ts docs/experiments/shape-picture/<파일>.hwp`

## 파일

앞 파일에 누적해서 바꿨다.

| 파일 | 바꾼 것 | 레코드에서 |
| --- | --- | --- |
| `default` | 그림 넣기만 | 91B. 효과 플래그 0, 원본 크기 9000×6000, 투명도 0 |
| `picture-line` | 그림 탭: 자르기 왼1·위2·오른3·아래4mm, 여백 왼1·오른2·위3·아래4mm, 밝기 3, 대비 −2, 투명도 5%. 선 탭: 빨강, 점선, 3mm, 투명도 7% | 자른 뒤 사각형 (283, 566, 8150, 4867), 여백 283·566·850·1133, 명암 −2, 밝기 3, 그림 투명도 13, 테두리 종류 2·굵기 850·투명도 18 |
| `effect-shadow` | 그림자: 첫 프리셋, 파랑, 53%, 흐리게 8pt, 크기 101%, 기울기 4°, 거리 7pt, 각도 47° | 플래그 bit 0. 투명도 0.53, 흐리게 800, 방향 47, 거리 700, 정렬 4, 기울기 x 4, 확대 y 1.01 |
| `effect-reflection` | 반사: 가운데 줄 3번째 프리셋, 크기 77%, 거리 7pt | 플래그 bit 3. 56B. 정렬 6, 끝 위치 0.77, 거리 700 |
| `effect-all` | 네온(주황 프리셋, 52%, 11pt), 옅은 테두리(3번째 프리셋, 8pt) | 플래그 0b1111. 네온 색에 색상 효과 (516, 1.75), 옅은 테두리 800 |
| `gray-invert` | 회색조, 그림 반전 | 그림 효과 1. 그림 반전은 SHAPE_COMPONENT 개체 요소 속성 bit 24 |
| `bw-watermark` | 흑백, 워터마크 | 그림 효과 2, 밝기 70, 명암 −50 |

## 결과

- 레코드 앞 78바이트(표 107)
  - 테두리 12바이트: 색, 굵기, 속성. 그리기 개체 테두리 선(표 86, 정정 89)에서 Outline style 1바이트를 뺀 것이다. 한글 기본 테두리는 검정, 굵기 33, 종류 0, 끝 모양 1, 화살표 크기 4·4, bit 30·31 켜짐이고, 이때 HWPX에는 `hp:lineShape`가 없다.
  - 꼭짓점: (x, y) INT32 쌍 4개(`hp:imgRect` `pt0`~`pt3`). 명세는 x 4개 다음 y 4개로 적었다. 그림을 넣을 때의 크기이고, 자르거나 크기를 바꿔도 그대로다.
  - 자른 뒤 사각형: left, top, right, bottom 좌표. 원본 이미지 좌표다(`hp:imgClip`). 오른쪽을 3mm 자르면 right가 9000 − 850이다.
  - 그림 여백: HWPUNIT16 왼쪽·오른쪽·위·아래(`hp:inMargin`).
  - 그림 정보 5바이트: 명암, 밝기, 효과, BinItem ID. 명세와 달리 명암이 먼저다(정정 11과 같다).
  - 테두리 투명도 BYTE(`hp:lineShape alpha`): 7%가 18이다.
  - 인스턴스 ID: HWPX `instid`와 같다.
- 그림 효과(표 108): 플래그 UINT32의 bit 0 그림자, bit 1 네온, bit 2 옅은 테두리, bit 3 반사. 블록도 이 순서다(`hp:effects`의 자식 순서와 같다).
  - 그림자(표 109): 명세 순서가 맞다. "정렬"은 HWPX `alignStyle`이고 4가 `CENTER`다. 대화상자 "기울기"는 기울기 x, "크기"는 확대 y다.
  - 반사(표 112): 명세는 53바이트라 적었지만 INT32·float 14개, 56바이트다. 첫 INT32 "반사 스타일"은 `alignStyle`이고 6이 `BOTTOM_LEFT`다. 대화상자 "크기" 77%는 끝 위치 0.77이다.
  - 색(표 113): 대화상자가 만든 색은 모두 타입 0(RGB, HWPX `type="RGB"`)이었다. 이때 타입, 0x00rrggbb, 효과 수 순서로 12바이트이고 효과는 (종류 INT32, 값 float) 쌍이다. 명세 표 113의 CMYK·ScRGB·HSL 칸은 오지 않는다.
  - 네온 프리셋의 색상 효과는 HWPX `SAT_MOD`인데 명세 표 115의 16이 아니라 516(0x204)으로 저장됐다.
- 끝 9바이트는 표 116이다: 원본 크기 HWPUNIT ×2(`hp:imgDim`), 그림 투명도 BYTE(`hp:img alpha`, 5%가 13). 표 107은 표 116을 가리키지 않는다. 저장소의 오래된 90바이트 레코드에는 투명도 바이트가 없다.
- "그림 반전"은 그림 레코드가 아니라 SHAPE_COMPONENT 개체 요소 속성 bit 24다(HWPX `reverse="1"`). 그리기 개체에서 bit 24는 글상자 유무였다(정정 101).
- 워터마크는 별도 비트가 없다. 밝기 70, 명암 −50 값으로만 저장된다. 회색조는 효과 1, 흑백은 효과 2다.
- 자르면 SHAPE_COMPONENT의 현재 크기가 자른 크기가 되고 scale matrix가 바뀐다(7867 / 9000 = 0.874111). 개체 공통 속성의 폭·높이는 여기에 그림 여백을 더한 값이다(7867 + 283 + 566 = 8716).

## 확인하지 않은 것

- 그림자 스타일 1 이상(대화상자의 두 번째·세 번째 프리셋 묶음). 여기서는 첫 프리셋(`OUTSIDE`, 0)만 썼다.
- 회전·대칭한 그림. 회전한 그림의 bit 25는 `shape-unknown-bits`(E52)에서 봤다.
- 캡션을 단 그림. 빌더로 만든 캡션 그림은 `builder-picture`에서 확인했다.
- RGB가 아닌 효과 색 타입. 대화상자로 만드는 방법을 찾지 못했다.

## 재현

```sh
npx tsx docs/experiments/scripts/dump-pictures.ts docs/experiments/shape-picture/*.hwp
```

원격 조작에서 파일 이름을 입력할 수 없어(모든 글자가 'a'로 입력됨) 'aa', 'aaa'…로 저장하고 Mac에서 복사해 지금 이름을 붙였다.
