# 문단 번호 8~10수준과 수준별 시작번호

문단 번호 레코드에서 시작 번호 뒤에 오는 수준별 시작번호와 8~10수준이 실제로 어느 자리에 저장되는지, 9·10수준 문단의 수준이 문단 모양 어디에 들어가는지 보려고 했다.

- 날짜: 2026-11-12
- 환경: macOS 한글. 앱 버전은 기록하지 않았다. 파일 버전은 5.1.1.0이다.
- 기반 파일: 없음. 한글에서 새 문서를 만들어 직접 설정하고 저장했다.

## 파일

| 파일 | 한글에서 설정한 것 |
| --- | --- |
| `levels-1-9-10.hwp` | 1수준 시작 번호 52, 2수준 5, 9수준 7. 9수준 번호 모양 i, ii, iii과 형식 `^9..`, 10수준 번호 모양 일, 이, 삼과 형식 `^1가.^9`. 본문에 1·9·10수준 문단 하나씩 |

## 결과

바이트에서 읽은 것이다(재현 명령의 출력).

- 수준별 시작번호 UINT32 7개는 1수준부터 차례로 저장된다. 1수준 52, 2수준 5가 각각 첫째와 둘째 자리에 있었다.
- 8~10수준의 시작번호 3개는 세 수준의 머리 정보·형식 뒤에 이어진다. 9수준의 7이 둘째 자리에 있었다.
- 시작 번호 UINT16도 52였다. 같은 파일의 기본 번호 레코드는 UINT16이 0, 1수준 시작번호가 1이라 두 값이 다르다. UINT16의 뜻은 미확인이다.
- 문단 모양 레코드는 58B로, 명세 표 43의 54B보다 4B 길다. 끝 UINT32는 1·9·10수준 문단에서 0, 8, 9였고, 속성1 bit 25~27은 0, 6, 6이었다.

한글 화면에서 본 것이다. 이 파일보다 앞서 저장한 같은 문서(시작번호만 1수준 52, 나머지 1)에서 관찰했다.

- 10수준 형식에 `^10`을 넣으면 `^1` 뒤에 글자 `0`으로 표시됐다(본문 "520").
- 번호 서식의 "번호 넣기" 목록에는 1~9수준만 있다. 10수준 번호를 넣는 코드는 찾지 못했다.
- 형식 `^1가.^9`는 본문에서 "52가.i"로 표시됐다.

## 결론

- 문단 번호 레코드의 구조는 `1~7수준 → 시작 번호 UINT16 → 수준별 시작번호 UINT32 ×7 → 8~10수준 → 확장 시작번호 UINT32 ×3`이고, 시작번호는 수준 순서대로다. 8수준 시작번호의 자리는 값을 바꿔 확인하지 않았다.
- 9·10수준 문단의 수준은 문단 모양 끝의 명세에 없는 UINT32에 있다. 8수준 문단은 확인하지 않았다.
