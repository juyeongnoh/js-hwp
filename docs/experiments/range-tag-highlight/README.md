# 문단의 영역 태그(PARA_RANGE_TAG)는 형광펜이다

명세 표 63은 영역 태그를 "형광펜, 교정 부호 등"에 쓴다고만 적고, 종류 값과 데이터 24비트의 뜻을 적지 않는다. 저장소의 HWP 133개에는 이 레코드가 하나도 없어 코덱의 읽기·쓰기를 실제 파일로 확인하지 못했다. 한글에서 형광펜, 교정 부호 20가지, 변경 내용 추적을 넣어 저장하고 어떤 기능이 이 레코드를 쓰는지, 값이 무엇인지 확인했다.

- 날짜: 2026-11-18
- 환경: Windows용 한글 2024. 파일 버전은 각 파일의 FileHeader를 따른다. 앱 버전은 기록하지 않았다.
- 기반: 한글 새 문서에 `AAAA BBBB CCCC`를 입력했다. 파일마다 앞 파일의 상태에 조작을 하나씩 더해 저장했다.
- 바꾼 곳: 없음. 모든 파일은 한글이 저장한 그대로다.

## 파일

글자 위치는 PARA_TEXT의 코드 단위 기준이다. 구역 첫 문단이라 `secd`·`cold` 컨트롤 16칸이 앞에 있어 `AAAA`는 16부터 시작한다.

| 파일 | 조작 | PARA_RANGE_TAG |
| --- | --- | --- |
| `highlight-yellow.hwpx` | `BBBB`에 노란 형광펜. 파일 형식 기본값이 HWPX라 실수로 저장됐다 | (HWPX) `<hp:markpenBegin color="#FFFF00"/>` … `<hp:markpenEnd/>` |
| `highlight-yellow.hwp` | 위와 같음, HWP로 저장 | `21–25 kind 2 data 0x00FFFF` |
| `highlight-colors.hwp` | `CCCC`에 빨간 형광펜, `AA BB`(위치 18–22)에 초록 형광펜을 노란 구간과 겹치게 칠함 | `18–23 kind 2 0x008000`, `23–25 kind 2 0x00FFFF`, `26–30 kind 2 0x0000FF` |
| `proofread-delete.hwp` | 첫 `AA`에 교정 부호 뺌표 | 영역 태그는 그대로(위치만 16 밀림). 뺌표는 PARA_TEXT의 필드 시작·끝(0x03, 0x04)과 ctrlId `%%*C`로 저장 |
| `track-insert.hwp` | 변경 내용 추적을 켜고 줄 끝에 ` DDDD` 입력 | 영역 태그는 그대로. 새 영역 태그 없음 |
| `proofread-all.hwp` | 새 문서에 `NN abcd efgh` 20줄을 쓰고 교정 부호 대화상자의 20가지를 줄마다 하나씩 넣음(아래 표) | 없음. 모두 필드다 |

본문의 모습은 한글 화면에서 형광펜 색이 칠해진 것을 보고 확인했다.

### `proofread-all.hwp`의 교정 부호

PARA_TEXT의 필드 시작 문자(0x03) 뒤 코드 단위를 ctrlId로 읽은 값이다. CTRL_HEADER의 ctrlId는 모두 `%unk`였다. 선택은 `abcd`(4글자)이고, 다르게 넣은 것만 따로 적었다.

| 줄 | 교정 부호 | 필드 | 비고 |
| --- | --- | --- | --- |
| 02 | 메모 고침표 | `%%mr` | 메모 칸에 메모가 생겼다. 처음 선택이 한 줄 아래로 잡혀 1번 줄이 아니라 2번 줄에 들어갔고, 고침표와 겹쳤다 |
| 02 | 고침표 | `%%*c` | |
| 03 | 뺌표 | `%%*C` | |
| 04 | 지움표 | `%%*d` | |
| 05 | 붙임표 | `%%*a` | |
| 06 | 줄 붙임표 | `%%*A` | 선택과 관계없이 문단 맨 앞에 빈 필드(시작·끝이 붙어 있음)로 들어갔다 |
| 07 | 줄 이음표 | `%%*i` | 한 줄 선택으로는 들어가지 않았다. 줄 끝에서 다음 줄 앞까지 선택하니 7번 문단 끝에서 시작해 8번 문단 맨 앞에서 끝나는 필드가 됐다 |
| 08 | 톱니표 | `%%*S` | |
| 09 | 생각표 | `%%*T` | |
| 10 | 칭찬표 | `%%*P` | |
| 11 | 줄표 | `%%*L` | |
| 12 | 자리 바꿈표 | `%%*n` | 한 낱말 선택으로는 들어가지 않았다. `abcd efgh`를 선택해 넣었다. 한 번 넣은 뒤 줄 서로 바꿈표를 넣자 사라져 다시 넣었다 |
| 13–14 | 줄 서로 바꿈표 | `%%*t` | 13번 줄 처음부터 14번 줄 끝까지 선택. 13번 문단 맨 앞에서 시작해 14번 문단 끝에서 끝난다. 14번 문단 맨 앞에 빈 필드 `%spl`이 함께 생겼다 |
| 14 | 오른 자리 옮김표 | `%%*r` | |
| 15 | 왼 자리 옮김표 | `%%*l` | |
| 16 | 넣음표 | `%sig` | 선택 없이 `abcd` 뒤에 커서를 두고 넣었다. 빈 필드다 |
| 17 | 띄움표 | `%sig` | 같음 |
| 18 | 부호 넣음표 | `%sig` | 같음. 내용에 `.`을 넣어야 했다("마침표와 쉼표만 넣을 수 있습니다") |
| 19 | 줄 바꿈표 | `%sig` | 같음 |
| 20 | 줄 비움표 | `%sig` | 같음 |

`%sig` 다섯 개는 CTRL_HEADER 길이가 51, 53, 57, 51, 51B로 달랐다. 종류는 필드 명령 쪽에 있는 것으로 보이지만 읽어 보지 않았다.

## 결론

- 형광펜은 PARA_RANGE_TAG로 저장된다. 종류는 2다.
- 데이터 24비트는 형광펜 색 COLORREF(`0x00BBGGRR`)의 아래 3바이트다. 노랑 `0x00FFFF`, 초록 `0x008000`, 빨강 `0x0000FF`. HWPX의 `markpenBegin color="#FFFF00"`과 같은 색이다.
- 끝 위치는 구간에 포함되지 않는다(반열린 구간). `BBBB`(21~24)가 `21–25`로 저장됐다.
- 위치는 PARA_TEXT 코드 단위다. 컨트롤 문자의 8칸도 센다. 뺌표 필드 16칸이 앞에 생기자 모든 구간이 16씩 밀렸다.
- 한글은 형광펜 구간을 겹치게 저장하지 않는다. 노란 구간 위에 초록을 겹쳐 칠하자 노란 구간이 `23–25`로 잘렸고, 항목은 시작 위치 순서였다.
- 교정 부호는 한글 2024 대화상자의 20가지 모두 영역 태그가 아니라 필드다. 명세가 영역 태그의 용도로 적은 "교정 부호"는 적어도 한글 2024에서는 쓰이지 않는다. 변경 내용 추적의 글자 넣기도 영역 태그를 만들지 않았다.
- 그래서 한글 2024 UI로 만들 수 있는 영역 태그는 종류 2(형광펜)뿐이었다.
- 코덱으로 다섯 HWP 파일을 읽고 다시 쓰면 BodyText의 모든 레코드가 원본과 바이트까지 같았다.

**확인하지 않은 것**

- 종류 2 말고 다른 종류 값을 쓰는 기능. 한글 2024보다 오래된 버전이 교정 부호를 영역 태그로 저장했는지, 변경 내용 추적의 지우기.
- 교정 부호 필드의 CTRL_HEADER 명령 문자열과, `%sig` 다섯 가지를 구분하는 값.
- 여러 문단에 걸친 형광펜이 문단마다 나뉘어 저장되는지.
- 겹치는 구간이나 끝 < 시작인 구간을 넣은 파일을 한글이 어떻게 여는지.

## 재현

파일은 한글에서 손으로 만들어 다시 생성할 수 없다. 영역 태그는 아래 명령으로 볼 수 있다.

```bash
npx tsx docs/experiments/scripts/dump-range-tags.ts docs/experiments/range-tag-highlight/highlight-yellow.hwp docs/experiments/range-tag-highlight/highlight-colors.hwp docs/experiments/range-tag-highlight/proofread-delete.hwp docs/experiments/range-tag-highlight/track-insert.hwp docs/experiments/range-tag-highlight/proofread-all.hwp
```

처음에는 `para-range-tag/` 폴더에 저장했다가 폴더 규칙에 맞게 이름을 바꿨다. `highlight-yellow.hwpx`는 `highlight-yellow.hwp.hwpx`로 저장된 것을 이름만 바꿨다.
