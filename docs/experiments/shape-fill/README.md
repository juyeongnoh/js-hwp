# 그리기 개체 SHAPE_COMPONENT의 채우기 정보

SHAPE_COMPONENT의 채우기 정보(표 28)는 DocInfo 테두리/배경과 같은 리더로 읽는다. 저장소 사각형은 모두 기본 단색 채우기라서, 한글 개체 속성 "채우기" 탭의 다른 선택이 같은 배치인지 확인했다. 대화상자에서 색 채우기 없음·색·그러데이션은 라디오 버튼이고, 그림은 별도 체크박스라 색이나 그러데이션과 함께 고를 수 있다. 탭 아래에 채우기 투명도가 있다.

- 날짜: 2026-11-24
- 환경: Windows용 한글 2024(파일 버전 5.1.2.0). 대화상자와 저장은 computer use로 직접 조작했다.
- 기반: `base.hwp`(`experiments/shape-shadow/base.hwp`의 사본, 기본 사각형). 각 파일은 앞 파일에 이어서 바꿨다.
- 그림: `solid-64.bmp`(`experiments/object-overlap-lock`에서 복사). `image`, `color-image`는 문서에 포함, `color-image-alpha`, `gradient-image`는 그림 체크박스를 다시 켜면서 "문서에 포함"이 꺼져 연결 그림이 됐다.
- 바꾼 곳: `BodyText/Section0` SHAPE_COMPONENT 오프셋 209(테두리 선 뒤)부터. 채우기 뒤에는 그림자 22바이트가 이어진다(정정 91).

| 파일 | 대화상자 | 종류 | 채우기 종류 뒤 바이트 (괄호: 종류 포함 전체) |
| --- | --- | --- | --- |
| `none` | 색 채우기 없음 | 0 | 추가 속성 길이 0 (전체 8B) |
| `base` | 색(면 흰색, 무늬 색 검정) | 1 | 색 12B, 길이 0, `00` (21B) |
| `gradient` | 그러데이션 기본값(세로, 기울임 90, 번짐 정도 255, 번짐 중심 50) | 4 | 그러데이션 21B + 색 2개, 길이 1, 번짐 중심 `32`, `00` (39B) |
| `image` | 색 채우기 없음 + 그림 | 2 | 그림 6B(채우기 유형 5 "크기에 맞추어", 명암·밝기·효과 0, BinItem 1), 길이 0, `00` (15B) |
| `color-image` | 색 + 그림 | **3** | 색 12B, 그림 6B, 길이 0, `00 00` (28B) |
| `color-alpha` | 색, 투명도 30% | 1 | 색 12B, 길이 0, **`4d`** (21B) |
| `color-image-alpha` | 색 + 그림, 투명도 30% | 3 | 색, 그림, 길이 0, **`4d 4d`** (28B) |
| `gradient-image` | 그러데이션 + 그림, 투명도 30% | **6** | 그러데이션, 그림, 길이 1, `32`, **`4d 4d`** (46B) |

- 블록 순서는 종류 비트와 관계없이 색, 그러데이션, 그림이다. DocInfo와 같다(정정 6~9).
- **채우기 끝의 바이트는 채우기 투명도다.** 30%가 77(255 × 0.3)이다. 켜진 종류마다 하나씩 있고, 한글은 같은 값을 쓴다. 정정 10에서 "뜻 모름"이라고 적은 바이트다. 그때는 셀 배경에서 값을 바꿔도 표시가 같았는데, 셀 배경 대화상자에는 투명도가 없다.
- 한글은 색 + 그림(3), 그러데이션 + 그림(6)을 저장한다. 색 + 그러데이션(5)은 대화상자로 만들 수 없다.
- 지금 코덱의 `readFill`은 그림 하나만 남겨, 3과 6은 다시 쓴 바이트가 달라진다. 그래서 `readShapeFill`이 대비책으로 채우기를 읽지 않고, 그 뒤 그림자까지 `trailing`에 원본 그대로 남긴다.

## 확인하지 않은 것

- 색과 그림의 투명도를 따로 정할 수 있는지(대화상자에는 칸이 하나다).
- 그러데이션 + 투명도만 켠 파일. 그러데이션 색 3개 이상.
- 연결 그림과 포함 그림의 BinData 차이.
