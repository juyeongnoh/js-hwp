# 실험

한글 프로그램을 오라클로 삼아 HWP 형식이나 동작을 확인한 실험 파일 모음이다. 결과 요약은 `../hangul-behavior.md`(동작)와 `../hwp-format.md`(형식)에 옮긴다.

## 목록

| 폴더                          | 확인한 것                                                       |
| ----------------------------- | --------------------------------------------------------------- |
| `fill-gradient-field-sizes/`  | 그러데이션 필드 크기: 명세 INT16과 실제 배치(유형 1B + 4B) 비교 |
| `fill-gradient-step-zero/`    | 번짐 정도 0이면 그러데이션이 그려지지 않음                      |
| `fill-trailing-unknown-byte/` | 채우기 끝의 알 수 없는 1바이트가 표시에 영향을 주는지           |
| `fill-multi-kind-priority/`   | 채우기 종류가 여러 개 켜졌을 때의 우선순위                      |
| `scripts/`                    | 실험 파일 생성·검사 스크립트 (공용)                             |

새 실험을 추가하면 이 표에 한 줄을 넣는다.

## 규칙

### 폴더

- **실험 하나에 폴더 하나**. 폴더 이름만 보고 무엇을 확인했는지 알 수 있게 짓는다.
- 이름은 `<영역>-<확인한 것>` 형식의 영어 kebab-case다. 예: `fill-gradient-step-zero`.
- **폴더 안에서 완결한다**. 실험 파일을 만든 기반 파일을 `base-<설명>.hwp`로 폴더에 넣는다. `fixtures/`처럼 나중에 덮어쓸 수 있는 파일을 기반으로 가리키지 않는다. 다른 실험과 같은 기반이면 복사해서 넣는다.

### 파일

- 실험 파일 이름은 무엇을 바꿨는지 드러나게 짓는다. 예: `step-50.hwp`, `3-color-image.hwp`.
- 실패하거나 무효가 된 시도도 지우지 말고 이유와 함께 남긴다. 예: `first-try-…`.
- **보안이 중요한 자료나 저작권이 있는 자료를 넣지 않는다**. HWP 안의 그림(BinData)과 미리보기(PrvImage)도 해당한다. 미리보기는 기반 파일의 것이 그대로 복사되므로, 기반 파일을 만들 때부터 주의한다.

### README

폴더마다 `README.md`를 두고 아래 순서로 쓴다.

1. 제목과 무엇을 왜 확인하려 했는지
2. 날짜, 환경(한글 버전과 OS), 기반 파일, 바꾼 곳
3. 파일 표: 파일, 바꾼 값, 결과
4. 결론
5. 재현: 저장소 루트에서 그대로 실행할 수 있는 명령. 생성 이름과 현재 이름이 다르면 대응도 적는다.

결과는 관찰한 것만 적는다. 본문에 그려진 모습인지 속성 창 값인지처럼 무엇을 보고 판단했는지 구분하고, 확인하지 않은 것은 미확인으로 적는다.

### 스크립트

- 생성·검사 스크립트는 `scripts/`에 둔다. 여러 실험이 같은 스크립트를 쓰므로 폴더마다 복사하지 않는다.
- 스크립트는 기반 파일 경로를 인자로 받는다. 저장소 안의 특정 파일 경로를 하드코딩하지 않는다.
- 스크립트는 생성한 파일을 다시 읽어, 의도한 바이트만 바뀌고 나머지 레코드와 스트림이 기반과 같은지 확인해 출력한다.

### 검증

- 실험 파일을 다시 만들거나 기반을 바꾸면, 폴더의 기반 파일로 다시 생성해 기존 파일과 바이트가 같은지 비교한다. 결과는 README의 재현 항목에 날짜와 함께 남긴다.
- 기반을 바꿔 바이트가 달라지면 한글에서 다시 열어 결과를 확인한다.
