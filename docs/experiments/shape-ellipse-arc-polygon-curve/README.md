# 타원·호·다각형·곡선 개체 속성(표 96, 99, 101, 103)

저장소에 이 네 도형이 없어서 새 문서에 하나씩 그려 HWP와 HWPX로 저장하고, 도형별 레코드를 명세 및 HWPX와 맞춰 봤다.

- 날짜: 2026-11-25
- 환경: macOS용 한글(Hancom Office HWP, 파일 버전 5.1.1.0). computer use로 조작했다.
- 파일: `shapes.hwp`, 같은 문서의 `shapes.hwpx`. 입력 → 도형에서 아래 순서로 그렸다.
  1. 타원: 끌어서 그림
  2. 호: 오른쪽 위에서 왼쪽 아래로 끌어서 그림
  3. 다각형(열림): 점 3개를 누르고 네 번째 점에서 두 번 누름
  4. 다각형(닫힘): 점 3개를 누르고 첫 점을 다시 누름
  5. 곡선: 점 3개를 누르고 네 번째 점에서 두 번 누름

## 결과

| 도형 | 레코드 | 명세 | 실제 |
| --- | --- | --- | --- |
| 타원 `$ell` | SHAPE_COMPONENT_ELLIPSE 60B | 표 96 | 같다. 속성 0, 중심 (7149, 4289), 제1축 (14298, 4289), 제2축 (7149, 0), 나머지 점 0 |
| 호 `$arc` | SHAPE_COMPONENT_ARC 25B | 속성 UINT32, 28B | 호 종류 BYTE 0, 중심 (0, 0), 제1축 (0, 8578), 제2축 (14298, 0) |
| 다각형 `$pol` | SHAPE_COMPONENT_POLYGON 40B | 점 수 INT16, x 배열, y 배열 | 점 수 4B, (x, y) 쌍 4개, 끝 4B(열린 것 0, 첫 점을 눌러 닫은 것 1. 닫힘 여부가 아니다, 아래 참고) |
| 곡선 `$cur` | SHAPE_COMPONENT_CURVE 43B | 점 수 INT16, x 배열, y 배열, 구간 종류 cnt−1 | 점 수 4B, (x, y) 쌍 4개, 구간 종류 `01 01 01`, 끝 0 4B |

- 모든 점은 HWPX와 같았다. 타원은 `hp:ellipse`의 `center`, `ax1`, `ax2`, `start1`, `end1`, `start2`, `end2`, 호는 `hp:arc type="NORMAL"`과 `center`, `ax1`, `ax2`, 다각형은 `hc:pt`, 곡선은 `hp:seg type="CURVE"`의 `x1, y1, x2, y2`다.
- 타원 속성 0은 HWPX `intervalDirty="0" hasArcPr="0" arcType="NORMAL"`과 맞는다.
- 닫힌 다각형은 점이 4개이고 마지막 점이 첫 점과 같았다. HWPX도 `hc:pt` 4개였다. 끝 4바이트는 HWPX에 대응하는 속성이 없다(뜻은 아래 "다각형·곡선 닫기" 참고).
- 점 수 4바이트는 INT32와 INT16 + 0 2바이트를 구분하지 못했다. 코덱은 UINT32로 읽는다.

## 호 종류

`shapes` 문서에서 호를 고르고 개체 속성 › 선 › "호 테두리"를 부채꼴, 활 순서로 바꿔 각각 HWP와 HWPX로 저장했다(`arc-pie`, `arc-chord`).

| 파일 | 호 테두리 | 호 레코드 첫 바이트 | HWPX `hp:arc type` |
| --- | --- | --- | --- |
| `shapes` | 호 | 0 | `NORMAL` |
| `arc-pie` | 부채꼴 | 1 | `PIE` |
| `arc-chord` | 활 | 2 | `CHORD` |

바뀐 것은 이 1바이트뿐이었다. 타원을 고르면 "호 테두리" 버튼이 비활성이고, 오른쪽 클릭 메뉴에도 호로 바꾸는 항목이 없었다.

## 호로 바꾼 타원 (Windows용 한글 2024)

macOS용 한글로는 타원을 호로 바꿀 수 없어서 Windows용 한글 2024(파일 버전 5.1.2.0)에서 새 문서에 타원을 그리고, 오른쪽 클릭 → "다각형 편집"으로 위쪽 편집점을 원 둘레를 따라 끌었다. 타원이 부채꼴 모양이 되고 "호 테두리"가 켜졌다. Windows에서 저장한 파일을 SMB로 가져와 이름을 바꿨다.

| 파일 | 상태 | 타원 속성(바이트 순) |
| --- | --- | --- |
| `ellipse-edit-pie.hwp` | 편집점을 끈 직후(호 테두리 부채꼴) | `02 01 01 00` |
| `ellipse-edit-arc.hwp` | 호 테두리 호 | `02 00 00 00` |
| `ellipse-edit-chord.hwp`, `.hwpx` | 호 테두리 활 모양 | `02 02 00 00`, HWPX `hasArcPr="1" arcType="CHORD" intervalDirty="0"` |

bit 1이 호로 바뀌었는지, 둘째 바이트(bit 8~15)가 호 종류다. 명세 표 97은 호 종류를 bit 2~9로 적었다(정정 99). bit 16은 편집점을 끈 직후에만 켜졌다.

## 호의 시작·끝점과 bit 16 (Windows용 한글 2024)

같은 크기의 타원 세 개를 그리고 위쪽 편집점을 오른쪽 끝, 아래 끝, 왼쪽 끝으로 끌어 바로 HWP와 HWPX로 저장했다(`ellipse-edit-angles`). 그다음 첫 타원만 개체 속성에서 아무것도 바꾸지 않고 "설정"을 눌러 HWP로 저장했다(`ellipse-edit-angles-dialog`).

- start1은 편집점을 놓은 곳(오른쪽 (24736, 7421), 아래 (12368, 14842), 왼쪽 (0, 7421)), end1은 처음 자리 (12368, 0)이었다. 모양은 1/4, 반원, 3/4 부채꼴이었다.
- 세 타원 모두 속성 bit 16이 켜져 있었지만 HWPX는 `intervalDirty="0"`이었다. "설정"을 누른 첫 타원만 bit 16이 꺼졌다.

## 다각형·곡선 닫기 (Windows용 한글 2024)

다각형 P1·P2(마지막 점을 두 번 눌러 끝냄), P3(첫 점을 다시 눌러 닫음)와 곡선 C1·C2를 그려 저장했다(`polygon-curve-drawn.hwp`). 다각형 편집 안의 "열린 다각형 닫기/닫힌 다각형 열기"로 P2·C2를 닫고 P3를 열어 저장했다(`polygon-curve-toggled.hwp`, `.hwpx`). 펜으로 직선을 그은 문서는 `polygon-pen.hwp`다. 모두 Windows에 마운트한 macOS 저장소 폴더에 바로 저장했다.

- 닫힘은 마지막 점이 첫 점과 같은 것으로만 나타났다. 닫기는 첫 점을 끝에 더했고(P2 4 → 5점, C2 4 → 5점·구간 4개), 열기는 마지막 점을 옮겼다(P3).
- 다각형 끝 4바이트는 첫 점을 눌러 닫으며 그린 P3만 1이었고, 열어도 1이었다. 메뉴로 닫은 P2는 0이었다. 앞에서 "열림 0, 닫힘 1"로 본 것은 틀렸다.
- 곡선 끝 4바이트는 닫아도 0이었다. 펜으로 그은 직선은 점 5개의 다각형이었다.

## 글상자·캡션·회전·대칭 (Windows용 한글 2024)

다각형·곡선 쌍에 각각 "도형 안에 글자 넣기"와 "캡션 넣기"를 하고, 다각형 하나는 회전각 30°, 곡선 하나는 좌우 대칭을 해서 HWP와 HWPX로 저장했다(`polygon-curve-textbox-caption-rotate`). 여섯 개체 모두 모델로 읽히고 구역 스트림이 바이트 단위로 같게 왕복했다. 회전각은 30으로 저장됐고(도 단위), 좌우 대칭은 개체 요소 속성 bit 0을 켰다. 글상자가 있는 개체만 bit 24가 켜졌다(정정 101, E50).

## 확인하지 않은 것

- 다각형 끝 4바이트의 뜻. 곡선 구간 종류 0(직선)을 만드는 조작.

- 타원 속성 bit 0과 bit 16의 뜻. start2·end2가 start1·end1과 1 다른 이유.
