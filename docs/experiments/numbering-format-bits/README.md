# 문단 번호 형식은 속성 bit 5부터 저장된다

명세 표 40은 문단 머리 정보 속성에 bit 0~4만 적고, 표 41의 번호 형식이 어디에 저장되는지는 적지 않는다. 한글에서 번호 모양을 바꿔 저장한 값과 비트를 직접 바꾼 사본으로 위치를 확인했다.

- 날짜: 2026-11-11
- 환경: macOS용 한컴오피스 한글 12.30.0(6544)
- 기반: `base-format-14.hwp`. 두 번째 문단 번호(`numbering[1]`) 1수준을 한글에서 ㊀㊁㊂(14)로 설정해 저장한 파일이다. 속성은 `0x1CC`(bit 2, 3, 6, 7, 8)다. 한글이 저장한 원본은 이후 같은 파일에 다시 저장하면서 남지 않았다. `format-16.hwp`에서 bit 5~9를 14로 되돌려 복원했으므로 cfb 라이브러리가 다시 쓴 컨테이너이고 `Sh33tJ5` 스트림이 더해져 있다. 레코드와 다른 스트림 내용은 한글 저장본과 같다.
- 바꾼 곳: `numbering[1]` 1수준 문단 머리 정보 속성의 bit 5~9

## 파일

| 파일 | bit 5~9 | 속성 | 결과 |
| --- | --- | --- | --- |
| `base-format-14.hwp` | 14 | `0x1CC` | 한글이 ㊀㊁㊂로 저장한 값 |
| `format-16.hwp` | 16 | `0x20C` | 설정 창 번호 모양 甲, 乙, 丙 |
| `format-31.hwp` | 31 | `0x3EC` | 본문 1, 2, 3. 설정 창 번호 모양 드롭다운은 빈칸 |

사용자가 17부터 31까지의 값도 넣어 봤고, 모두 본문 1, 2, 3, 드롭다운 빈칸이었다. 남은 파일은 `format-31.hwp`뿐이다. bit 5~9에는 31보다 큰 값이 들어가지 않는다. 그 위의 비트는 `../numbering-format-high-bits`에서 확인했다.

## 결론

- 번호 형식은 bit 5부터 저장된다. 14 = `01110`(bit 6~8), 16 = `10000`(bit 9)으로 표 41의 값과 맞는다.
- 한글 기본 개요 번호의 속성 `0x10C`(가, 나, 다 = 8), `0x2C`(①②③ = 1)도 같은 위치로 읽힌다(`dump-numbering-heads.ts`로 확인).
- 범위 밖 값은 본문에서 1, 2, 3으로 그린다. bit 10 이상은 `../numbering-format-high-bits`에서 따로 확인했다.

## 재현

저장소 루트에서 실행한다.

```bash
npx tsx docs/experiments/scripts/patch-numbering-head.ts docs/experiments/numbering-format-bits/base-format-14.hwp <출력 폴더>/format-16.hwp 1 0 5 9 16
```

`format-31.hwp`는 마지막 인자를 31로 바꾼다. 2026-11-12에 이 폴더의 기반 파일로 다시 생성해 처음 만든 파일과 바이트가 같음을 확인했다.
