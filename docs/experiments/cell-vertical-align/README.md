# 셀 세로 정렬이 LIST_HEADER 속성 어디에 저장되는지

셀 LIST_HEADER의 문단 리스트 속성(표 65) bit 5~6이 세로 정렬이다. 문단 리스트 헤더가 문단 수 INT32 + 속성 UINT32라면(정정 83, `list-header-para-count`) 속성은 오프셋 4부터다. 코덱은 그동안 오프셋 2부터 읽어 세로 정렬을 늘 "위"로 읽었다. 한글이 세로 정렬을 어디에 쓰는지 확인하고, LIST_HEADER를 고친 코덱이 쓴 파일을 한글에서 열어 봤다.

- 날짜: 2026-11-19
- 환경: Windows용 한글 2024. 앱 버전은 기록하지 않았다.
- 기반: 한글 새 문서에 1×4 표를 넣었다(만들기 대화상자, 줄 1·칸 4). 셀에 `위`, `가운데`, `아래`를 입력하고, 넷째 셀에는 `1`~`5`를 다섯 문단으로 입력해 행을 높였다. 첫 셀은 위, 셋째 셀은 아래로 표/셀 속성 > 셀 > 세로 정렬에서 바꿨다. 둘째·넷째 셀은 기본값(가운데) 그대로다.
- 바꾼 곳: 없음. 한글이 저장한 그대로다.

## 파일

| 파일 | 셀 | LIST_HEADER 앞 8바이트 | 속성(오프셋 4) bit 5~6 |
| --- | --- | --- | --- |
| `top-center-bottom.hwp` | 위 | `01000000 00000000` | 0 |
| | 가운데 | `01000000 20000000` | 1 |
| | 아래 | `01000000 40000000` | 2 |
| | 1~5 (기본) | `05000000 20000000` | 1 |

## 결론

- **세로 정렬은 오프셋 4의 속성 bit 5~6이다.** 0 위, 1 가운데, 2 아래. 명세 표 65의 값과 같다.
- **한글이 새로 만든 셀의 세로 정렬은 가운데다.**
- 코덱(2026-11-19 수정 뒤)은 이 파일을 위, 가운데, 아래, 가운데로 읽는다. 코덱으로 다시 쓴 파일과, 빌더로 만든 표(셀을 위·가운데·아래·지정 안 함으로 둠)를 한글에서 열자 정렬이 그대로 그려졌다. 지정하지 않은 셀은 가운데로 그려졌다. 두 파일은 저장소에 넣지 않았다.

**확인하지 않은 것**

- 속성의 다른 비트(텍스트 방향 bit 0~2, 줄바꿈 bit 3~4)와 세로쓰기 셀.
