# 이미지 글머리표의 이미지 여부와 BinData ID

명세 표 42는 이미지 글머리표 여부 `INT32`에 이미지 ID를 넣고, 이미지 정보를 4B(대비, 밝기, 효과, ID)로 적는다. 실물 레코드는 25B였고 이미지 여부는 1이었다. ID가 1B인지 2B인지 가리려고 ID 위 바이트만 바꿨다.

- 날짜: 2026-11-14
- 환경: macOS 한글. 앱 버전은 기록하지 않았다. 파일 버전은 5.1.1.0이다.
- 기반 파일: `base.hwp`. 한글에서 문단 세 개에 이미지 글머리표 두 개를 적용해 저장했다. BinData는 BIN0001.png, BIN0002.png, BIN0003.jpg다.
- 바꾼 곳: 첫째 글머리표 레코드의 오프셋 22, 1바이트.

## 파일

| 파일 | 첫째 글머리표 오프셋 14~24 | BinData | 결과 |
| --- | --- | --- | --- |
| `base.hwp` | `01 00 00 00` `00 00 00` `03 00` `20 00` | 0001, 0002, 0003 | 기반 |
| `id-0x0103.hwp` | `01 00 00 00` `00 00 00` `03 01` `20 00` | 0001, 0002, 0003 | 그 글머리표의 그림이 표시되지 않음 |
| `id-0x0103-resaved.hwp` | `01 00 00 00` `00 00 00` `00 00` `20 00` | 0001, 0002 | `id-0x0103.hwp`를 한글에서 다시 저장 |

둘째 글머리표(BIN0001)는 세 파일 모두 `01 00`으로 같다. 표시 결과는 사용자가 한글에서 열어 확인했다.

## 결론

- 이미지 여부 `INT32`는 0 또는 1이다. ID가 아니다.
- 이미지 정보는 5B이고 ID는 오프셋 21의 `UINT16`으로 본다. 한글은 0x0103을 없는 ID로 다뤘고, 다시 저장하며 ID를 0으로 바꾸고 쓰이지 않게 된 BIN0003을 버렸다.
- 오프셋 22가 0이어야 하는 예약 바이트일 가능성은 ID 256 이상의 실물 없이는 배제하지 못했다.
- 이미지 여부 1, ID 0인 레코드를 한글이 어떻게 표시하는지는 확인하지 않았다.
