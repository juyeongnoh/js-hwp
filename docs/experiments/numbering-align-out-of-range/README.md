# 문단 머리 정렬 값 3

명세 표 40은 문단 머리 정렬(bit 0~1)에 0 왼쪽, 1 가운데, 2 오른쪽만 적는다. 남은 값 3을 넣었을 때 한글의 동작을 확인했다.

- 날짜: 2026-11-12
- 환경: macOS용 한컴오피스 한글 12.30.0(6544)
- 기반: `base-right-20mm.hwp`. 두 번째 문단 번호(`numbering[1]`) 1수준이 甲乙丙(16), 정렬 오른쪽, 번호 너비를 자릿수에 맞춤 끔, 자동으로 내어쓰기 끔, 너비 조정 20 mm(5669), 본문과의 간격 70 %, 글자 모양 아이디 7이다(속성 `0x202`). 한글이 저장한 원본은 이후 같은 파일에 다시 저장하면서 남지 않았다. `../numbering-format-high-bits/bit-10.hwp`에서 bit 10을 되돌려 복원했으므로 cfb 라이브러리가 다시 쓴 컨테이너이고 `Sh33tJ5` 스트림이 더해져 있다. 레코드와 다른 스트림 내용은 한글 저장본과 같다.
- 바꾼 곳: `numbering[1]` 1수준 문단 머리 정보 속성의 bit 0~1

## 파일

| 파일 | bit 0~1 | 속성 | 결과 |
| --- | --- | --- | --- |
| `base-right-20mm.hwp` | 2 | `0x202` | 오른쪽 |
| `align-3.hwp` | 3 | `0x203` | 본문은 왼쪽으로 그린다. 설정 창 정렬 드롭다운은 빈칸 |

## 결론

- 값 3은 본문에서 왼쪽(0)으로 그린다. 범위 밖 번호 형식과 같은 모양이다(`../numbering-format-bits`).
- js-hwp는 명세대로 0~2만 쓴다. 읽을 때 3을 바꾸지는 않는다.

## 재현

```bash
npx tsx docs/experiments/scripts/patch-numbering-head.ts docs/experiments/numbering-align-out-of-range/base-right-20mm.hwp <출력 폴더>/align-3.hwp 1 0 0 1 3
```

2026-11-12에 이 폴더의 기반 파일로 다시 생성해 처음 만든 파일과 바이트가 같음을 확인했다.
