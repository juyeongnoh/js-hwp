# 별건 목록

## 코드

- [ ] **COLORREF 최상위 바이트 손실**: 배경색 `FF FF FF FF`를 다시 쓰면 `FF FF FF 00`이 된다. `reader.color()`가 최상위 바이트를 버린다. `0xFFFFFFFF`가 "색 없음"을 뜻하는지도 함께 확인. `border-fill.test.ts`에 `it.fails`로 표시해 둠.
- [ ] **`ImageFillMode.None` 이름**: 한글 표기는 "원래 크기에 비례하여". 동작을 드러내는 이름으로 바꿀지 결정.

## 한글 실측

- [ ] **이미지 효과 값**: 회색조·흑백 등으로 바꿔 저장했을 때 효과 바이트가 바뀌는지 확인. 지금까지 0만 봤다.
- [ ] **이미지 명암·밝기 음수**: −20 같은 음수로 저장해 INT8로 읽히는지(`ec`) 확인.
- [ ] **대각선 kind 0과 2**: 대각선 선 종류를 "없음", 파선 등으로 바꿔 LineStyle 대응 확인. 지금까지 1(실선), 3(점선)만 확인했다.
- [ ] **복수 채우기 종류의 우선순위**: 한글은 하나만 저장하지만, 두 비트가 켜진 파일(단색+그러데이션, 종류 5)도 오류 없이 열린다. 어떤 종류를 우선해 그리는지 확인. 지금까지는 종류 5에서 속성 창이 그러데이션을 보였을 뿐이고, 그 시험 파일은 번짐 정도가 0이라 실제로 무엇을 그리는지는 몰랐다. 조합 3(단색+이미지), 5, 6(그러데이션+이미지), 7(전부)을 비교한다.
- [ ] **그러데이션 색 위치 배열** (Windows 필요): 색 수 > 2일 때의 위치 INT32 × num 배치. macOS 한글은 3색 이상을 설정할 수 없다.
- [ ] **정오표의 Windows 후속 항목** (Windows 필요): `hwp-5.0-errata.md`의 "Windows에서 후속 확인할 사항" 참고.
