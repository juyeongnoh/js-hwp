## 1. 한글 파일 구조 요약

HWP 파일은 CFB(Compound File Binary) 구조를 가진다. 내부적으로 폴더의 역할을 하는 스토리지, 파일의 역할을 하는 스트림을 가진다.

> 📂 = 스토리지<br/>📄 = 스트림

**[표 2] 파일 전체 구조**

| 설명            | 구별 이름                                                               | 길이(바이트) | 레코드 구조 | 압축/암호화 |
| --------------- | ----------------------------------------------------------------------- | ------------ | ----------- | ----------- |
| 파일 인식 정보  | 📄 FileHeader                                                           | 고정         |             |             |
| 문서 정보       | 📄 DocInfo                                                              | 가변\*       | ✅          | ✅          |
| 본문            | 📂 BodyText<br/>├ 📄 Section0<br/>├ 📄 Section1<br/>└ 📄 ...            | 가변         | ✅          | ✅          |
| 문서 요약       | 📄 \005HwpSummaryInformation                                            | 고정         |             |             |
| 바이너리 데이터 | 📂 BinData<br/>├ 📄 **BIN0001.jpg**<br/>├ 📄 **BIN0002.png**<br/>└ 📄 ...       | 가변         |             | ✅          |
| 미리보기 텍스트 | 📄 PrvText                                                              | 고정         |             |             |
| 미리보기 이미지 | 📄 PrvImage                                                             | 가변         |             |             |
| 문서 옵션       | 📂 DocOptions<br/>├ 📄 \_LinkDoc<br/>├ 📄 DrmLicense<br/>└ 📄 ...       | 가변         |             |             |
| 스크립트        | 📂 Scripts<br/>├ 📄 DefaultJScript<br/>├ 📄 JScriptVersion<br/>└ 📄 ... | 가변         |             |             |
| XML 템플릿      | 📂 XMLTemplate<br/>├ 📄 Schema<br/>├ 📄 Instance<br/>└ 📄 ...           | 가변         |             |             |
| 문서 이력 관리  | 📂 DocHistory<br/>├ 📄 VersionLog0<br/>├ 📄 VersionLog1<br/>└ 📄 ...    | 가변         | ✅          | ✅          |

### COLORREF

파일에 R, G, B, 최상위 바이트 순서로 저장된다(4B). **최상위 바이트는 0이 아닐 수 있다.** 의미는 모른다. 셀 배경에서 `FF FF FF FF`는 색 없음, `FF FF FF 00`은 흰색이다. 다른 필드와 다른 값은 확인하지 않았다.

\*\* 미확인. 위치 배열은 3색 이상 그러데이션이 필요한데 macOS 한글은 2색까지만 설정할 수 있다. 그림 효과는 0만 확인했다. 명암·밝기의 음수도 확인하지 않았다.

\*\*\* 켜진 종류마다 1바이트이고 채우기 없음에는 없다. 블록과 같은 순서(단색, 그러데이션, 이미지)로 각 종류의 투명도다. **0이 불투명, 255가 완전히 투명하다**(보통의 alpha와 반대 방향). 한글 2024 그리기 개체 "채우기" 탭의 투명도 칸이 값/255를 %로 보인다(30% → `4d`(77), 200 → 78%). 색 + 그림이면 한글은 `4d 4d`처럼 같은 값을 쓰고, 두 값을 다르게 넣으면 각 종류에 따로 적용된다. 화면에 적용되는 곳은 그리기 개체 채우기뿐이다. DocInfo 테두리/배경(셀, 문단, 쪽, 글자) 대화상자에는 이 칸이 없고, 값이 있어도 그리지 않지만 다시 저장할 때 보존한다(정정 92, E41, `experiments/fill-alpha`). HWPX에서는 `alpha`라고 부른다.

명세 표 28은 공통 꼬리를 이미지 채우기 구획 아래에 `DWORD`·`BYTE`·`DWORD`·`BYTE[size]` 네 행으로 적는다. 실제로는 위 표의 `DWORD`와 `BYTE[size]` 두 필드뿐이고, 명세는 같은 필드를 두 번 적었다. 명세의 둘째 조건식 `type & 0x0000001`은 `0x0000004`의 오타다.

**한글이 저장한 채우기 부분**

```text
채우기 없음  00 00 00 00 | 00 00 00 00
단색         01 00 00 00 | ff ff ff ff 99 99 99 00 ff ff ff ff | 00 00 00 00 | 00
이미지       02 00 00 00 | 0f 4b 32 00 01 00                   | 00 00 00 00 | 00
그러데이션   04 00 00 00 | (아래)                              | 01 00 00 00 | 32 | 00
```

그러데이션: 빨강→파랑, 기울임 90, 가로·세로 중심 0, 번짐 정도 255, 번짐 중심 50.

```text
04 00 00 00     채우기 종류: 그러데이션
01              유형
5a 00 00 00     기울임 90
00 00 00 00     가로 중심 0
00 00 00 00     세로 중심 0
ff 00 00 00     번짐 정도 255
02 00 00 00     색 수 2
ff 00 00 00     빨강
00 00 ff 00     파랑
01 00 00 00     추가 채우기 속성 길이 1
32              번짐 중심 50
00              투명도 0
```

## 4. 본문 (BodyText)

구역마다 `BodyText/Section{N}` 스트림이 하나 있다. 스트림은 문단 리스트다. 공식 명세와 다른 곳은 굵게 표시했다. 근거는 `hwp-5.0-errata.md`의 정정 50~53과 E22에 있고, 절마다 따로 적은 근거가 더 있다.

### 레코드 트리

레코드 헤더의 레벨은 계층의 깊이다(4.1). 레코드는 부모 다음에 자식이 오는 순서로 저장된다. 그래서 레벨 N+1 레코드의 부모는 앞에서 가장 가까운 레벨 N 레코드다. 명세는 부모를 직접 적지 않는다. 저장소 HWP에서 레벨이 2 이상 건너뛰는 곳은 없었다.

```text
PARA_HEADER (0)
├ PARA_TEXT (1)
├ PARA_CHAR_SHAPE (1)
├ PARA_LINE_SEG (1)
└ CTRL_HEADER 'tbl ' (1)
  ├ TABLE (2)
  ├ LIST_HEADER (2)        ← 셀 1
  ├ PARA_HEADER (2)        ← 셀 1의 문단. LIST_HEADER의 자식이 아니다
  │ └ PARA_TEXT … (3)
  ├ LIST_HEADER (2)        ← 셀 2
  └ …
```

**표 셀의 문단은 LIST_HEADER와 같은 레벨의 형제다.** 어느 셀의 문단인지는 LIST_HEADER의 문단 수로 센다. 꼬리말과 바탕쪽의 리스트도 같은 모양이다. 머리말·각주·미주·숨은 설명은 확인하지 않았다.

### 문단의 영역 태그 (PARA_RANGE_TAG)

근거는 `hwp-5.0-errata.md`의 정정 72와 E29에 있다.

**[표 63] 문단의 영역 태그.** 12B 항목이 문단 헤더의 range tag 정보 수만큼 이어진다.

| 오프셋 | 자료형 | 길이(바이트) | 설명 |
| ------ | ------ | ------------ | ---- |
| 0 | UINT32 | 4 | 시작 위치 |
| 4 | UINT32 | 4 | 끝 위치. **이 위치의 글자는 구간에 들지 않는다** |
| 8 | UINT32 | 4 | 태그. 상위 8비트는 종류, 하위 24비트는 데이터 |

- 위치는 PARA_TEXT 코드 단위다. **컨트롤 문자의 8칸도 센다.** 구역 첫 문단에서는 `secd`·`cold` 16칸 뒤부터 글자다.
- **종류 2는 형광펜이다. 데이터는 형광펜 색 COLORREF(`0x00BBGGRR`)의 아래 3바이트다.** 노랑 `0x00FFFF`, 초록 `0x008000`, 빨강 `0x0000FF`. HWPX의 `<hp:markpenBegin color="#FFFF00"/>`에 해당한다.
- 다른 종류 값은 보지 못했다. **명세가 함께 적은 교정 부호는 영역 태그가 아니라 필드로 저장된다**(아래).
- 한글이 저장한 형광펜 항목은 서로 겹치지 않고 시작 위치 순서다.

**교정 부호 필드.** 모두 필드 쌍(0x03, 0x04)이고 CTRL_HEADER ctrlId는 `%unk`다. 부호는 필드 시작 문자 뒤의 ctrlId로 구분된다. 줄 이음표와 줄 서로 바꿈표는 필드가 문단 경계를 넘는다.

| 필드 시작 문자의 ctrlId | 교정 부호 |
| --- | --- |
| `%%*c` `%%*C` `%%*d` `%%*a` `%%*A` `%%*i` | 고침표, 뺌표, 지움표, 붙임표, 줄 붙임표, 줄 이음표 |
| `%%*S` `%%*T` `%%*P` `%%*L` | 톱니표, 생각표, 칭찬표, 줄표 |
| `%%*n` `%%*t` `%%*r` `%%*l` | 자리 바꿈표, 줄 서로 바꿈표, 오른 자리 옮김표, 왼 자리 옮김표 |

#### 캡션과 문단 리스트 헤더

개체 공통 속성 bit 29가 켜져 있으면 CTRL_HEADER의 첫 자식이 캡션 LIST_HEADER(30바이트)다. 표에서는 TABLE 레코드보다 앞에 온다. 캡션 문단은 이 레코드의 형제로 뒤따른다. 근거는 정정 83, 84와 E32다.

| 오프셋 | 자료형 | 설명 |
| --- | --- | --- |
| 0 | **INT32** | 문단 수. **명세 표 65는 INT16.** 한글은 읽을 때 쓰지 않는 것으로 보인다 |
| 4 | UINT32 | 문단 리스트 속성(표 65). 셀과 같은 배치다(정정 86) (`textDirection`, `lineWrap`, `verticalAlign`, `listUnknownBits`) |
| 8 | UINT32 | 캡션 속성: bit 0–1 방향(0 왼쪽, 1 오른쪽, 2 위, 3 아래), bit 2 캡션 폭에 여백 포함 (`side`, `fullSize`) |
| 12 | HWPUNIT | 캡션 폭. 왼쪽·오른쪽일 때만 쓴다 (`width`) |
| 16 | HWPUNIT16 | 캡션과 개체 사이 간격 (`gap`) |
| 18 | HWPUNIT | 텍스트 최대 길이 = 개체 폭 (`maxWidth`) |
| 22 | 8바이트 | **명세에 없음. 늘 0** (`trailing`) |

표 셀 등 다른 LIST_HEADER도 앞 8바이트(문단 수 INT32, 속성 UINT32)는 같다. 한글은 읽을 때 문단 수를 쓰지 않고, 다음 LIST_HEADER까지의 형제 문단을 그 리스트의 문단으로 본다.

**문단 리스트 속성(오프셋 4, UINT32).** 셀 LIST_HEADER로 확인했다(정정 85, E33, `experiments/list-header-properties`, `experiments/cell-vertical-align`). 괄호는 HWPX 속성과 셀 모델 필드다.

| 비트 | 설명 |
| --- | --- |
| 0~2 | 글자 방향: 0 가로, 1 세로·영문 눕힘, 2 세로·영문 세움 (`subList textDirection`, `textDirection`) |
| 3~4 | 줄바꿈: 0 일반, 1 자간을 조정해 한 줄 유지, 2 내용에 따라 폭이 늘어남 (`subList lineWrap`, `lineWrap`) |
| 5~6 | 세로 정렬: 0 위, 1 가운데, 2 아래. 새 셀은 1, 한글이 만든 아래 캡션은 0. 캡션 대화상자의 "오른쪽 가운데"·"오른쪽 아래"가 이 값이다(E34) (`subList vertAlign`, `verticalAlign`) |
| 16 | 셀: 안 여백 지정 (`tc hasMargin`, `hasMargin`) |
| 17 | 셀: 셀 보호 (`tc protect`, `protect`) |
| 18 | 셀: 제목 셀 (`tc header`, `header`) |

한글은 범위 밖 값(글자 방향 3~7, 줄바꿈 3, 세로 정렬 3)과 bit 21~31을 다시 저장할 때 지우지 않는다. 코덱은 bit 0~6을 모든 LIST_HEADER에 공통으로 읽는다(`readListHeader`). 문단 리스트를 가진 모델(셀, 캡션, 머리말·꼬리말, 각주·미주, 숨은 설명, 바탕쪽, 메모)은 모두 `ParagraphList`를 확장해 같은 필드로 읽고 쓴다. 범위 밖 글자 방향·줄바꿈은 필드에 그대로, 세로 정렬 3과 bit 7~31은 `listUnknownBits`로 보존한다. 셀은 여기에 bit 16~20을 더 읽는다. 세로 정렬이 없으면 셀은 가운데(1), 나머지는 위(0)로 쓴다. 비트 배치는 셀과 캡션(세로 정렬)으로만 한글에서 확인했다. 저장소 파일의 꼬리말은 세로 정렬 아래(2), 바탕쪽·메모는 위(0)였다. 셀·캡션이 아닌 리스트는 헤더 8바이트 뒤(머리말·꼬리말·바탕쪽 26B, 메모 8B)를 해석하지 않고 `listTrailing`으로 보존한다. 새로 만들면 헤더 8바이트만 쓴다.

**셀 LIST_HEADER (46B 또는 47B).** 공통 헤더 8B, 셀 속성(표 80) 26B, 명세에 없는 12~13B다. 괄호는 HWPX와 `TableCell` 필드다.

| 오프셋 | 자료형 | 설명 |
| --- | --- | --- |
| 0 | UINT32 | 문단 수 |
| 4 | UINT32 | 리스트 속성 (위 표) |
| 8 | UINT16 | 열 주소, 0부터 (`cellAddr colAddr`, `col`) |
| 10 | UINT16 | 행 주소, 0부터 (`cellAddr rowAddr`, `row`) |
| 12 | UINT16 | 열 병합 수 (`cellSpan colSpan`, `colSpan`) |
| 14 | UINT16 | 행 병합 수 (`cellSpan rowSpan`, `rowSpan`) |
| 16 | HWPUNIT | 셀 폭 (`cellSz width`, `width`) |
| 20 | HWPUNIT | 셀 높이 (`cellSz height`, `height`) |
| 24 | HWPUNIT16 ×4 | 안 여백: **왼쪽, 오른쪽, 위, 아래** (`cellMargin`, `margins`). 명세는 "4방향"이라고만 적었다 |

### 그리기 개체 (`gso `, SHAPE_COMPONENT)

그리기 개체와 그림은 CTRL_HEADER ctrlId가 모두 `gso `다(정정 77). 개체의 종류와 모양은 그 아래 레코드에 있다. 명세 4.3.9.2는 SHAPE_COMPONENT 한 레코드에 개체 요소 속성, 테두리 선, 채우기, 글상자가 이어지는 것처럼 적었지만 실제 배치는 아래와 같다. 근거는 정정 77, 89~91과 E37~E39, `experiments/object-common-props`, `experiments/shape-outline-style`, `experiments/shape-shadow`다. 코덱은 `readShapeComponent`/`writeShapeComponent`이고 모델은 `ShapeComponent`다(괄호 안 이름). 지금은 `gso ` 컨트롤을 `unknown`으로 읽고 `shapeComponent` 필드에 둔다.

```
CTRL_HEADER 'gso '            ctrlId + 개체 공통 속성 (placement)
  [LIST_HEADER 캡션]          캡션 문단이 형제로 뒤따른다 (placement.caption)
  [PARA_HEADER ...]
  SHAPE_COMPONENT             아래 표 (shapeComponent)
    [LIST_HEADER 글상자]      글상자 문단이 형제로 뒤따른다 (childRecords)
    [PARA_HEADER ...]
    SHAPE_COMPONENT_RECTANGLE 등 도형별 레코드 (사각형은 shapeComponent.rectangle, 그 밖은 childRecords)
```

**SHAPE_COMPONENT.** 오프셋은 사각형(행렬 쌍 1개) 기준이다. 사각형 252B, 그림 196B다.

| 오프셋 | 자료형 | 설명 |
| --- | --- | --- |
| 0 | UINT32 ×2 | 개체 컨트롤 ID(`$rec`, `$pic` 등). 문단에 놓인 개체는 **두 번** 쓴다(명세의 GenShapeObject) (`shapeId`) |
| 8 | INT32 ×2 | 묶음 안의 X, Y 오프셋 (`groupOffsetX`, `groupOffsetY`) |
| 16 | WORD | 묶인 횟수 (`groupLevel`) |
| 18 | WORD | local file version. 한글 2024는 1 (`localVersion`) |
| 20 | UINT32 ×2 | 처음 폭·높이 (`initialWidth`, `initialHeight`) |
| 28 | UINT32 ×2 | 현재 폭·높이 (`width`, `height`) |
| 36 | UINT32 | 속성: bit 0 수평 반전, bit 1 수직 반전. **한글은 명세에 없는 bit 19, 24, 26, 29도 쓴다. 뜻 모름** (`flipHorizontal`, `flipVertical`, `unknownBits`) |
| 40 | HWPUNIT16 | 회전각. 단위 미확인 (`rotation`) |
| 42 | INT32 ×2 | 회전 중심. 한글은 폭·높이의 절반 (`rotationCenter`) |
| 50 | WORD | scale/rotation 행렬 쌍 수 cnt. 쓸 때는 배열 길이 |

| 196 | 13B | 테두리 선 정보. 그리기 개체(`$lin` `$rec` `$ell` `$arc` `$pol` `$cur`)만. **명세 표 86은 11B** (`line`) |
| 209 | 가변 | 채우기 정보(표 28). DocInfo 테두리/배경과 같은 배치. 단색은 21B (`fill`) |
| 230 | 22B | **명세에 없음.** 그림자와 인스턴스 ID. 명세 표 81은 여기에 글상자 12B를 적었다 (`shadow`, `instanceId`, `afterInstanceId`) |

그림은 Rendering 정보(오프셋 196)에서 레코드가 끝나고, 그림 고유 정보는 자식 SHAPE_COMPONENT_PICTURE에 있다.

**테두리 선 정보(13B).**

| 오프셋 | 자료형 | 설명 |
| --- | --- | --- |
| 0 | COLORREF | 선 색 (`color`) |
| 4 | **INT32** | 선 굵기. 0.12mm = 33. **명세는 INT16** (`width`) |
| 8 | UINT32 | 속성: bit 0~5 선 종류(실선 1), 6~9 끝 모양(0 round, 1 flat), 10~15·16~21 시작·끝 화살표 모양, 22~25·26~29 시작·끝 화살표 크기, 30·31 시작·끝 화살표 채움 (`style`, `endCap`, `startArrow`, `endArrow`, `startArrowSize`, `endArrowSize`, `startArrowFill`, `endArrowFill`) |

**채우기 뒤 22B.**

| 오프셋 | 자료형 | 설명 |
| --- | --- | --- |
| 0 | UINT32 | 그림자 종류: 0 없음, 1~4 평행(왼쪽 위, 오른쪽 위, 왼쪽 아래, 오른쪽 아래), 5~8 기울임(같은 순서), 13 축소, 14 확대. HWPX `hp:shadow type` (`shadow.kind`, `ShapeShadowKind`) |
| 4 | COLORREF | 그림자 색. 기본 `#B2B2B2`. 그림자가 없어도 들어 있다 (`shadow.color`) |

| 16 | UINT32 | 인스턴스 ID. HWPX `hp:rect` 등의 `instid`. 개체마다 다르고 다시 저장해도 그대로다 (`instanceId`) |
| 20 | BYTE | **뜻 모름.** 늘 0 (`afterInstanceId`) |
| 21 | BYTE | 그림자 투명도 0~255. 0이 불투명. 대화상자 30% = 77. HWPX `alpha` (`shadow.transparency`) |

**글상자 LIST_HEADER(33B).** 명세 표 89·90의 글상자 정보는 SHAPE_COMPONENT가 아니라 그 자식 LIST_HEADER에 있고, 순서도 명세와 반대다(정정 91). 공통 헤더 8B(문단 수, 리스트 속성) 뒤에 왼쪽·오른쪽·위·아래 여백 HWPUNIT16 ×4(기본 1mm = 283), 텍스트 최대 폭 HWPUNIT(= 도형 폭), 명세에 없는 0 13B가 온다. 코덱은 아직 해석하지 않고 `childRecords`로 보존한다.

**사각형 개체 속성(SHAPE_COMPONENT_RECTANGLE, 33B).** SHAPE_COMPONENT의 마지막 자식이다. 코덱은 `readShapeRectangle`/`writeShapeRectangle`, 모델은 `ShapeRectangle`이다(정정 93, E42, `experiments/shape-rectangle`).

| 오프셋 | 자료형 | 설명 |
| --- | --- | --- |
| 0 | BYTE | 모서리 곡률(%). 한글 대화상자의 직각 0, 둥근 모양 20, 반원 50. 곡률 지정은 0~50 (`cornerCurvature`) |
| 1 | **INT32 ×2 ×4** | 꼭짓점 (x, y) 4개. **명세는 x 4개 다음 y 4개.** 왼쪽 위부터 시계 방향으로 (0, 0), (폭, 0), (폭, 높이), (0, 높이)이고, 폭·높이는 SHAPE_COMPONENT의 처음 폭·높이다. 크기를 바꿔도 그대로다 (`points`) |

코덱은 사각형 레코드가 SHAPE_COMPONENT의 마지막 자식이고 CTRL_HEADER 아래에 그 뒤 레코드가 없을 때만 모델로 읽는다. 그렇지 않거나 33B보다 짧으면 `childRecords`에 원본 그대로 둔다. 33B 뒤의 바이트는 `trailing`으로 보존한다.

코덱은 앞에서부터 해석할 수 있는 데까지만 모델로 읽는다. ID가 두 번 오지 않거나, 행렬보다 짧거나, 행렬 원소가 유한하지 않으면 SHAPE_COMPONENT 전체를 `childRecords`에 원본 그대로 둔다. 채우기는 읽은 값을 다시 써서 원본과 같을 때만 `fill`로 두고, 채우기나 그림자를 읽지 못하면 그 뒤 바이트를 `trailing`에 남긴다.

| **29** | **원고지 문서에서 bit 22와 함께 켜졌다. 의미 모름** |

쪽 테두리/배경 대화상자의 "적용 쪽"은 비트 두 개로 저장한다. 테두리는 첫 쪽 제외 = bit 3, 첫 쪽만 = bit 8, 배경은 bit 4와 bit 9다. 모두는 둘 다 0이다.

자식 레코드는 `PAGE_DEF`(40B), `FOOTNOTE_SHAPE` 두 개(각주, 미주), `PAGE_BORDER_FILL` 세 개(양쪽, 짝수 쪽, 홀수 쪽) 순서다. **바탕쪽이 있으면 그 뒤에 LIST_HEADER와 형제 문단이 온다**(표 셀과 같은 모양).

**[표 133] 각주/미주 모양**

| 오프셋 | 자료형 | 길이(바이트) | 설명 |
| ------ | ------ | ------------ | ---- |
| 0 | UINT32 | 4 | 속성 |
| 4 | WCHAR | 2 | 사용자 기호 |
| 6 | WCHAR | 2 | 앞 장식 문자 |
| 8 | WCHAR | 2 | 뒤 장식 문자 |
| 10 | UINT16 | 2 | 시작 번호 |
| 12 | **4B** | **4** | 구분선 길이. **명세는 HWPUNIT16** |
| 16 | HWPUNIT16 | 2 | 구분선 위 여백 |
| 18 | HWPUNIT16 | 2 | 구분선 아래 여백 |
| 20 | HWPUNIT16 | 2 | 주석 사이 여백 |
| 22 | UINT8 | 1 | 구분선 종류 |
| 23 | UINT8 | 1 | 구분선 굵기 |
| 24 | COLORREF | 4 | 구분선 색 |
| 전체 길이 | | **28** | |

**[표 135] 쪽 테두리/배경**: 속성 4B, 간격 HWPUNIT16 ×4, 테두리/배경 ID UINT16(**1부터 센다**). **전체 길이 14B.** 쪽 테두리와 쪽 배경은 이 ID가 가리키는 테두리/배경 하나에 함께 들어간다.

**[표 136] 쪽 테두리/배경 속성**

| 비트 | 뜻 |
| ---- | ---- |
| 0 | 위치. **0 종이 기준, 1 쪽 기준** (명세는 반대로 적었다) |
| 1 | 머리말 포함 |
| 2 | 꼬리말 포함 |
| 3~4 | 채울 영역: 0 종이, 1 쪽, 2 테두리 |

bit 5 이상에 쓰레기 값이 들어 있는 파일이 있다.

### 메모

근거는 `hwp-5.0-errata.md`의 정정 70, 71과 E28에 있다.

- 본문의 메모 자리는 필드 쌍이다. 필드 시작의 CTRL_HEADER ctrlId는 `%unk`, 문단 텍스트의 필드 시작 문자 뒤에는 `%%me`가 있다.
- 메모 내용은 **문서의 마지막 구역, 마지막 문단의 자식**으로 컨트롤 뒤에 모여 있다. 메모마다 `MEMO_LIST`(UINT32 메모 번호, 1부터), `LIST_HEADER`, 형제 문단이 온다. 다른 구역의 메모도 여기 있다.
- 메모 모양은 구역 정의의 메모 모양 ID(26B 뒤 영역 오프셋 30)가 가리킨다.

**[표 154] 필드 시작 CTRL_HEADER** (ctrlId 뒤)

| 자료형 | 길이(바이트) | 설명 |
| ------ | ------------ | ---- |
| UINT32 | 4 | 속성. bit 0 읽기 전용에서도 수정 가능, bit 15 내용 수정됨 |
| BYTE | 1 | 기타 속성 |
| WORD + WCHAR[] | 2 + 2×len | 명령 문자열. 메모는 `MEMO/…` |
| UINT32 | 4 | 문서 안 고유 아이디 |
| | **가변** | **명세에 없음. 메모 필드는 메모 번호 UINT32** |

필드 끝 문자(0x04) 뒤의 6 코드 단위에도 값이 있다. 메모 필드에서는 `%me`와 메모 번호가 들어 있었다. 뜻은 확인하지 않았고 그대로 보존한다.
